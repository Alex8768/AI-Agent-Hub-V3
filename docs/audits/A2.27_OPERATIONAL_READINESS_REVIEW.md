# A2.27 Operational Readiness Review

## Scope

Operational review across CI workflows, test posture, release discipline, and runtime packaging.

Reviewed artifacts:

- `.github/workflows/ci.yml`
- `.github/workflows/ci-pro.yml`
- `.github/workflows/ci-cpu.yml`
- `.github/workflows/ci-selfhosted.yml`
- `docker-compose.yml`
- `docker/Dockerfile.app`
- `scripts/test.sh`
- `scripts/smoke.sh`

## Current Posture

- CI coverage is strong for unit/integration and release-gate contract checks.
- Branch-level automation is active and recently green for `pro-v3.1-dev`.
- Runtime packaging exists for local/dev/prod (`Dockerfile` + `docker-compose`).
- Smoke/test scripts exist and cover end-to-end API behavior.

## Risk Register

### R1 (Medium) — CI overlap and policy fragmentation

- Multiple workflows (`ci.yml`, `ci-cpu.yml`, `ci-pro.yml`, self-hosted) have partially overlapping responsibilities.
- Risk: drift in required checks and duplicated cost/noise.
- Recommendation: define single source of truth for required checks and map each workflow to explicit policy role.

### R2 (Medium) — Coverage not enforced as release gate

- Tests run broadly, but no enforced coverage threshold is visible in CI workflows.
- Risk: regressions can pass with declining test depth.
- Recommendation: add explicit coverage threshold check in release-gate policy path.

### R3 (Medium) — Production compose includes insecure defaults

- `docker-compose.yml` has development-style defaults and plaintext credentials for several services.
- Risk: unsafe reuse in production-like environments.
- Recommendation: split dev vs production compose profiles and move secrets to secured env management.

### R4 (Low/Watch) — Runtime matrix can diverge from local scripts

- Local scripts (`scripts/test.sh`, `scripts/smoke.sh`) and CI jobs are both robust but not centrally versioned as policy artifacts.
- Risk: expectations drift between local validation and CI validation.
- Recommendation: publish a canonical "validation contract" document and keep scripts/workflows aligned to it.

## Strengths

- Release-gate CI artifacting is now present (`release-gate-report` in `ci-pro.yml`).
- Qdrant integration tests are explicitly provisioned and health-checked.
- Hosted and self-hosted paths provide broad runtime confidence.
- Full-suite local runs remain consistently green.

## Operational Readiness Verdict

- **Engineering CI readiness:** strong.
- **Release-governance readiness:** strong but should be consolidated.
- **Production operations readiness:** moderate (requires hardening of deployment configs/secrets practice).

## Recommended Next Actions (Backlog)

1. Consolidate CI required-check policy matrix and document canonical required statuses.
2. Add coverage threshold enforcement to release-gate.
3. Create production-safe deployment profile (separate from dev compose defaults).
4. Add explicit runbook for local vs CI validation contract.
