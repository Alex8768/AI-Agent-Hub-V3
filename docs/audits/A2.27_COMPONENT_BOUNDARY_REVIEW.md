# A2.27 Component Dependency & Boundary Review

## Scope

This review checks layer boundaries and import direction across:

- `src/core`
- `src/layers`
- `src/services`
- `src/api`
- `src/infrastructure`

## Boundary Model (Target)

- `core` should stay independent from `api/services/layers`.
- `layers` should avoid direct dependency on `api`.
- `services` should orchestrate layers/core and avoid depending on API schema contracts.
- `api` can depend on services/layers as delivery boundary.
- `infrastructure` should remain an implementation detail behind contracts/adapters.

## Findings

### F1 (Medium) — Service depends on API schemas

- File: `src/services/search/search_service.py`
- Current import: `from src.api.schemas import SearchRequest, SearchResult`
- Risk: introduces reverse dependency from application service to delivery layer.
- Impact: lowers portability/reuse of service layer outside FastAPI boundary and complicates future UI/API versioning.

### F2 (Low/Watch) — Layer modules directly import DB models

- Files:
  - `src/layers/pro/graph_rag/graph/store.py`
  - `src/layers/pro/memory/stores/sqlite_memory_store.py`
  - `src/layers/base/export/export_manager.py`
- Current pattern: direct imports from `src.infrastructure.database.models.*`
- Risk: tighter coupling between capability layers and persistence implementation.
- Impact: acceptable for current MVP speed, but can slow future backend swaps.

### F3 (Positive) — No obvious top-layer inversion from core

- `src/core` has no direct imports from `src/api`, `src/services`, or `src/layers` in this scan.
- This preserves core contract isolation and keeps architecture direction mostly healthy.

## Assessment

- Overall boundary health: **good**, with one meaningful cleanup target (`F1`).
- Priority refactor target (post-audit backlog): extract shared search DTOs/contracts from `src/api.schemas` into neutral contract module for service usage.

## Recommended Actions (Backlog, not in this patch)

1. Move search request/response models used by `SearchService` into a service-neutral contract location (`src/core/contracts` or `src/services/search/contracts`).
2. Keep API layer as mapper/adapter to these contracts.
3. For DB-coupled layer modules, define explicit repository protocol boundaries before broader persistence evolution work.
